# IT and Computer Science Portfolio Roadmap

This roadmap defines 30 substantial, independently verifiable projects. Status describes repository evidence, not intent. Existing projects are tracked separately and are not retroactively counted as complete against these specifications. New project source code, scripts, build tooling, and dependencies must not use Python.

## Portfolio delivery order

The build order balances foundational reusable experience, practical applications, systems work, and capstones. Projects are released one milestone at a time; each milestone must have runnable setup instructions and passing automated checks before its status advances. Shared libraries are introduced only after at least two projects demonstrate a real common need.

## Shared completion checklist

Each project release needs a problem statement and feature list; architecture and limitations; modular source with meaningful errors/logging; dependency manifest and reproducible setup; `.gitignore` and secret-free `.env.example` when configuration is needed; validation and security boundaries; SQL schema/migrations when applicable; automated unit and integration tests; CI quality checks; API documentation where relevant; setup, usage, examples and screenshots or a reproducible demo in the README; and contribution/licensing guidance. Docker is used when it improves reproducibility and is supported by the target environment. Credentials and personal data are never committed.
